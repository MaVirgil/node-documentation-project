Functions as values

With the exception of the primitive data types, everything in JavaScript is an object, including functions. This means that functions can be used like any other value in the language: they can be assigned to variables, passed as arguments, returned from functions and stored in data structures or in object fields.

Treating functions like this is called having functions as "first-class citizens", and enables a wealth of very powerful functionality, the basics of which will be detailed in the later sections of this page.

Function signatures

In Javascript there is nothing stopping you from calling a function with more or less arguments than the function expects. On one hand this can make it difficult to realize if you're using a function wrong, and it also puts a greater expectation on the provider of the function to validate the arguments properly. On the other hand, it frees the developer from having to define multiple overloaded functions in situations where one or more parameters are optional. Callback functions

As mentioned at the top of this page, the fact that functions are values in JavaScript, enable them to be passed as arguments to other functions. A function passed to another function is called a "callback function", and this can be very useful when you know you want something done, and how you want it done, but want to let another piece of logic dictate when or if it is done. A very common example of this is with an eventListener in client-side javascript: Say you want to fetch some data to populate a table on your website, but only when the user presses a 'fetch data' button. Now you can define a function called something like fetchData() {...} where you decide exactly how this data should be fetched, and what should be done with it.
