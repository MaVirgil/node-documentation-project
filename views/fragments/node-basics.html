What is node.js?

Node.js is a JavaScript runtime that runs outside of the web browser, enabling the development of server-side JavaScript applications.

While Node.js does come with a standard library of functionalities (which includes modules like fs for interacting with the file system, and path for working with file and directory paths), it is important to keep in mind that Node.js is just the tool that allows the developer to develop, build and run JavaScript applications outside of a browser environment - you're still just writing JavaScript code.

The NPM package manager

Node.js comes with a package manager aptly called the 'node package-manager' (or npm for short), which is used for managing and installing dependencies, as well as publishing your own packages. Dependencies declared with the node package-manager live in the package.json file at the root-directory of the project, and can be installed with the command npm install. Declaring and installing a new dependency is done with the command npm install <package-name>. It is also possible to initialize a new Node.js project with the command npm init.

The package.json file can contain metadata about the project (e.g. versioning information), run scripts, as well as a declaration of dependencies. Much of this metadate is mostly relevant if you wish to publish your code as a node package , and can therefore be omitted. Using node packages

Node packages are hosted in the npm registry, but usually you will probably find the documentation, guides, code examples etc. on the package's GitHub repository before seeing the npm registry. Most of the time though, you will discover useful packages by searching around for a solution to a problem or an annoyance.

Bigger packages like the web-framework express.js - used for this site, more on that later - are very well known, and often serve as the starting point of a project, but there are millions of smaller packages that solve very specific problems, and it can be hard to know when to add another dependency to your project versus implementing the solution yourself.

Node.js makes it incredibly easy to install dependencies in your project - with a simple command you can have pretty much any functionality you want! So if it's so easy to do, why not just make your project depend on everything?

Need to capitalize a string? npm install capitalize.

Need to escape special characters in a string to use it in a regular expression? npm install regex-escape.

Need to find out if a number is even? npm install is-even.

Soon enough your project will work exactly like you want it to, and you won't even have had to move a single proverbial muscle. The primary issue here is that you probably don't really know what is actually in your code anymore, even if you think you understand what every dependency you've installed does. See, many dependencies have dependencies of their own, and those dependencies might also have dependencies, and soon enough you're downloading a whole web of unkown code to your computer, your server, or even serving it to clients all around the world.

In most cases this will not be a big issue outside of bloated bundle-sizes resulting in sluggish perfomance or slow page loads, but it does make your project vulnerable to things like supply-chain attacks, where a bad actor gains control over some dependency, and uses it to spread malicious code downstream - you may have heard of the widespread Shai-Hulud worm which compromised over 400 node packages in 2026.

Another thing to consider is that an over-reliance on dependencies (especially smaller utility packages), can rob you of great learning opportunities. There can obviously be many reasons to work on a project, but if a primary goal is to become better at writing code, it might be worth trying to implement some functionality or tool yourself, even if a ready-made and well-tested solution already exists.
