The client-server model

The client-server model describes one of the fundamental mechanisms behind the communication and data flow of distributed systems. In a client-server relationship, the client reaches out with a request to a server, which processes the request and sends back a response. The most common example of the client-server relationship, is that between the web browser as the client, and the backend system that serves the webpage content as the server. In reality, many of the servers in such relationships are themselves clients in other relationships, made so by the fact that they might fetch external data from an API, or even be part of a microservice architecture.

Source: geeksforgeeks.org

In order for the client and the server to communicate effectively, this request-response flow uses protocols, which determine how communication between the parties is established and processed.

By far the most common protocol is the HyperText Transfer Protocol (HTTP), which serves as the foundation for the entire web.

Communicating with HTTP

When making an HTTP request to a URL, the client defines an HTTP-method, which is a semantic indication of the kind of operation that is desired. Most common is the GET method, which communicates the intent of fetching some kind of data. Every time you click a link or refresh a tab in your browser, a GET request is sent in order to fetch the data required for it to render the page you want. To see this in action, navigate to the 'network' tab of your browser dev-tools, and refresh this page.

Now you'll see a whole host of (hopefully) successful GET requests that your browser made, in order to fetch the HTML, CSS, images, fonts and scripts necessary to render this page:

Outside of the GET method used to fetch data, the most common HTTP-methods include POST, PUT, PATCH and DELETE. As mentioned before, these methods mostly carry a semantic meaning, and it is up to the server how they are interpreted. Due to this, there is - for example - no absolute consensus as to the precise meaning and difference between PUT, PATCH and POST, but the generally accepted use-case for each is as follows:

HTTP-method Description
GET Fetch data
POST Create data
PUT Replace data
PATCH Update data
DELETE Delete data
