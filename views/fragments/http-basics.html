The client-server model

The client-server model describes the fundamental mechanism behind the communication and data flow of distributed systems. In a client-server relationship, the client reaches out with a request to a server, which processes the request and sends back a response. The most common example of the client-server dichotomy is the relationship between the web browser as the client, and the backend system that serves the webpage content as the server. In reality, most of the servers in such relationships, are themselves clients in other relationships, made so by the fact that they might fetch external data from an API, or even be part of a microservice architecture.

Source: geeksforgeeks.org

In order for the client and the server to communicate effectively, this request-response flow uses protocols, which determine how communication between the parties is established and processed

By far the most common protocol is the Hyperlink Transfer Protocol (HTTP), which serves as the foundation for the entire internet.

Communicating with HTTP

When making an HTTP request to a URL, the client defines an HTTP-method, which is a semantic indication of the kind of operation that is desired. Most common is the GET method, which communicates the intent of fetching some kind of data. Every time you click a link or refresh a tab in your browser, a GET request is sent in order to the fetch the data required for it to render the page you want. To see this in action, navigate to the 'network' tab of your browser dev-tools, and refresh this page.
