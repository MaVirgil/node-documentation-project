Overview

JavaScript was developed in the mid-nineties for use in the Netscape Navigator, while later being adapted into every mainstream browser. JavaScript allows the development of dynamic client-side interfaces, where the website responds directly to the user's actions, without having to fetch a new HTML-page for every action.

Coming from type-safe languages like Java or C#, JavaScript can come across as very permissive, allowing you to write a whole lot of weird code, that it will then try it's best to execute in the most predictable manner possible. This can often lead to a lot of initial confusion, which mostly comes down to two features of the language: JavaScript is both dynamically and weakly typed, meaning that variables are not bound to a single data type and can change at runtime, and that expressions combining different data types will attempt to convert between types as nesessary in a process called type coercion.

These two factors make JavaScript very flexible to use, but they also lead to a series of "quirks", some of which there will be examples of further down on this page.

Data types

The most commonly used data types in JavaScript are:

Number

A 64-bit signed type representing a numeric value. Outside of the possible range of numbers, three distinct non-numeric values exist that are counted as being a Number:

  • infinity representing positive infinity
  • -infinity representing negative infinity
  • NaN represents the absence of a valid number (e.g. in the case of division by zero or other invalid mathematical operations)

String

Boolean

A binary value representing either true or false.

Empty values

Javascript has two values representing the absence of data: null and undefined. A variable which has not yet been initialized, or has no value will resolve to undefined, and while there are more or less intricate differences between the two, in modern JavaScript null is often the lesser-used.

Type coercion

Of special note is the coercion of a given value to a boolean that happens in boolean expression. Many values that could be considered "empty" are evaluted to the value of false when converted to a boolean. This includes the number 0, an empty string "", an empty array [] and the value undefined. These are called "nullish" values (as opposed to the opposite - "truthy" values). Unlike many other cases where type coercion can be a source of frustrating bugs and unexpected behaviour, this boolean coercion can be incredibly useful, and it means that checking if a String is empty, for example, is as easy as writing if (!someString).

Given the above description, one might expect the expression 10 + '5' to evaluate to 15, but this is where some of those "quirks" of coercion come in: The + operator is used in expressions to add two numbers together, but it is also used to concatenate two string values, and because the String type is the only type that can represent values of all other types, it is at the top of the type hierarchy in JavaScript, so when a String operator like + is used in an expression containing a string value, the other value is always coerced into a string as well.
