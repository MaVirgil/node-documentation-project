Overview

JavaScript was developed in the mid-nineties for use in the Netscape Navigator browser, while later being adapted into every mainstream browser. JavaScript allows the development of dynamic client-side interfaces, where the website responds directly to the user's actions, without having to fetch a new HTML-page for every action.

Coming from type-safe languages like Java or C#, JavaScript can come across as very permissive, allowing you to write a whole lot of weird code, that it will then try it's best to execute in the most predictable manner possible. This can often lead to a lot of initial confusion, which mostly comes down to two features of the language: JavaScript is both dynamically and weakly typed, meaning that variables are not bound to a single data type and can change at runtime, and that expressions combining different data types will attempt to convert between types as nesessary in a process called type coercion.

These two factors make JavaScript very flexible to use, but they also lead to a series of "quirks", some of which there will be examples of further down on this page.

Data types

The most commonly used data types in JavaScript are:

Number

A 64-bit signed type representing a numeric value. Outside of the possible range of numbers, three distinct non-numeric values exist that are counted as being a Number:

  • infinity representing positive infinity
  • -infinity representing negative infinity
  • NaN represents the absence of a valid number (e.g. in the case of division by zero or other invalid mathematical operations)

String

A String represents text, and can be declaread with either "double quotes" or 'single quotes'. A so-called template literal can also be declared with `backtics`, allowing you to embed values directly into the string:

Boolean

A binary value representing either true or false.

Empty values

Javascript has two values representing the absence of data: null and undefined. There are both semantic and functional differences between these two values: while undefined represents a variable with no assigned value, null represents the explicit absence of a value, and will never automatically be produced by the language. There are also some slight quirks with the way that null is implemented, resulting, for example, in the expression typeof null resolving to Object. While some built-in functions of the runtime environment (like node or the JavaScript engine built into browsers) do return null represent a missing value, undefined is by far the more common value of the two. It is also the value that is automatically given to a variable which has not yet been initialized.

Object

An object in JavaScript is a composite data type and fundamentally just consists of a collection of key-value pairs, not unlike a Struct in languages like C, or even a Table in Lua. Unlike a struct which just carries data and no behavior, a number of language features in JavaScript enable an object to carry both unexposed state through closures, and behaviour through functions-as-values (more on this later).

Of special note is the coercion of a given value to a boolean that happens in boolean expression. Many values that could be considered "empty" are evaluted to the value of false when converted to a boolean. This includes the number 0, an empty string "", an empty array [] and the value undefined. These are called "falsey" values (as opposed to the opposite - "truthy" values). Unlike many other cases where type coercion can be a source of frustrating bugs and unexpected behaviour, this boolean coercion can be incredibly useful, and it means that checking if a String is empty, for example, is as easy as writing if (!someString).
