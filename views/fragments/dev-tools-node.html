Hot-reloading

It's incredibly annoying and slow to have to relaunch your project every time you make a tiny change. Luckily there is a solution to this through the concept of "hot-reloading", where your project files are observed and every time a change is made, the project relaunches. One very popular tool for this is Nodemon, which can be installed globally on your computer with the console command npm install -g nodemon. Once installed, simply substitute the node command with nodemon when running your files, and the process will automatically restart every time a change is registered.

Nodemon can be configured pretty widely, and even used with other programming languages but for simple use cases, very similar functionality is actually baked into node.js by default by using the --watch flag when running your code with node: node --watch app.js.

Linting

A linter is a static-analysis tool that can help you catch and fix syntax issues, potential bugs, unoptimized code and inconsistent code style, all within your editor of choice. There are more or less opionionated and configurable linters for every language, but for JavaScript the most popular by far is ESLint, which can be installed in your project by running the npm command npm init @eslint/config@latest, at which point you can configure it by editing the eslint.config.js file.

Reading environment variables

Environment variables are values that are passed to your application at execution, and can be used to make it more configurable and adaptable to different environments (testing, development, production, etc.). They are also very often used for sensitive values like API keys or tokens which are needed by the code, but should not be present in the source files. Using node run-scripts

On this page we have looked at a couple of different ways to run a node project with node commands. The problem with these is that you need to remember them, and write them every time you run your application. This might not be a huge issue for you as long as you are actively working on your project, and it is relatively simple, but give your project to a team-member or yourself 3 months from now, and having to know remember those commands becomes really problematic. Luckily we can define scripts with node, that we can use to run more complex commands easily and fast. These scripts are declared in the package.json file, and can be run with npm run <script-name>.
